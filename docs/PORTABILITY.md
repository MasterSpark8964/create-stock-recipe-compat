# 当前兼容范围（0.3.6）

本文描述当前源码的设计范围，不将接口支持等同于第三方模组实测通过。历史变化见 [CHANGELOG](../CHANGELOG.md)。

## 环境与结构

构建目标为 Minecraft 1.20.1、Java 17、Forge 47.4.18、Create 6.0.8-289、JEI 15.20.0.130。元数据允许 Forge [47.4.18,48)、Create [6.0.8,6.0.9)、JEI [15.20.0.130,16)；这不是对范围内所有组合的验收声明。

这是独立客户端附属 Mod，没有整合包路径、KubeJS 依赖或专用于「无限模板」的配方 ID。两处客户端 Mixin 分别接入 JEI 转移和本附属 Mod 材料条目的库存分配。原 Create 网络、包裹和服务器处理代码不作替换。独立服务器连接场景仍未单独验收。

## 直接 JEI 转移

只从 INPUT 读取物品候选与数量，忽略催化剂及输出槽的材料需求；必需非物品输入拒绝整单。候选包含 NBT 时使用严格匹配，无 NBT 时保留普通物品匹配。第一项有效物品输出默认用于显示及数量换算；无物品输出可使用批次模式，概率与多输出语义需用户自行选择批次计数。

不能从通用 JEI 槽接口推断隐藏材料、能源、燃料、随机结果或任意模组机器规则。候选数量不一致时取最大值，可能多请求材料。JEI 展示用 NBT 也可能造成比真实配方更严格的匹配。

## 递归补料

查询原版工作方块的配方类型：crafting、smithing、smelting、blasting、smoking、stonecutting。模组和数据包注册在这些类型下、符合相应接口的配方可参与。自定义机器类型不会因继承 CraftingRecipe 而被自动纳入。

- 原料优先从库存预留，不同需求共享同一份剩余库存；候选选择支持回溯。
- 初次规划考虑中间配方的产出数量与余量，阻止活跃路径中的配方循环。
- 锻造选择具体模板、基底、添加物，再调用配方自身的 matches/assemble，核对实际产物是否满足目标。
- 锻造适用标准三槽、每个非空槽一个物品的语义；自定义额外消耗、概率产出或服务器专有逻辑不保证兼容。
- 原生非锻造的特殊动态配方不自动推断；燃料、返还容器与机器执行不规划。

递归结果固定为实际叶子材料；后续加量按首次方案缩放，不重新选配方、不保证全局最省材料。移除后重新加入才能按当前库存重新规划。

## 排除规则

- Create 序列组装、粉碎、研磨、机械合成等自定义机器类型不展开；直接选择其 JEI 配方请求物品材料的能力保持独立。
- SmithingTrimRecipe（含子类）或使用 SMITHING_TRIM 序列化器的配方不展开。
- EnchantedBookItem（含子类）或带 StoredEnchantments 的产物不递归制作；动态锻造的实际产物也经过该检查。
- 已有附魔书可直接作为库存；普通装备锻造升级及基底附魔继承保留。

未暴露上述类型、序列化器或物品/NBT 标记的第三方自定义纹饰/附魔机制，无法仅凭名称可靠识别，因此不承诺全部自动排除。

## 性能与边界

单次规划内复用候选与锻造预览；库存匹配避免重复判断；子配方直接分配仅为相关且可用的库存建立列。缓存不跨越后续转移；另有一秒失败预览冷却。

当前默认值与固定边界见 [配置文档](CONFIGURATION.md)。保护触及时报告相应限制，而不是伪装成确定缺料。时间预算是协作式的，无法保证零卡顿，也没有当前版本的性能测量数据。

测试与构建事实见 [验证记录](VALIDATION.md)。第三方同位置 Mixin、配方动态逻辑和跨版本环境都可能影响兼容性。
